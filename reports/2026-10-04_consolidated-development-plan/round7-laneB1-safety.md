## Checked and holds (short)

- **The controls and the canary.** The B9-class rules catch every shape the plan names when the name is bare or quoted: plain env lines, `SetCredential=passphrase:`, TOML inline tables, `docker run -e`, keyword arguments, `**Passphrase:**` labels, a whole assignment in a code span, and plain or code-spanned table cells. That is 12 of 12 controls. The canary found 20 of 20 classes in every run.
- **The trio's editable installs** (plan L504, L853). In `JuniperCascor1`'s 3.14 tree, the finders map data-client 0.5.0 to `juniper-data-client/juniper_data_client` and cascor 0.11.0 to `juniper-cascor/src`.
- **Canopy's own F-S10 exposure.** Canopy refuses every key it cannot send and unbinds the clients' fallback to the raw environment variables (`src/secrets_util.py` L143–266; `src/settings.py` L471–504). So its only F-S10 path is cascor's 409, as the plan says (L83, L986). `JuniperCanopy1` runs data-client 0.5.0 as a wheel that the trio route never touches; it is safe only because of that screening.
- **XC-SENTRY's six variables** (L340). The services read `JUNIPER_CASCOR_SENTRY_DSN`, `JUNIPER_DATA_SENTRY_DSN` and `JUNIPER_CANOPY_SENTRY_DSN`, plus the legacy `CANOPY_SENTRY_DSN`, through their settings (cascor `settings.py` L501, data `settings.py` L236, canopy `settings.py` L281 and L658–666). `configure_sentry` does nothing when the DSN is empty. The DSN-name census found no other variable; `CASCOR_SENTRY_DSN_FILE` only names compose's secret source (`docker-compose.yml` L1195).
- **S0.11's walk.** It is the walk sentry-sdk does (`utils.py` L818–821, L900–947). `raise … from None` inside `except` is skipped (the in-memory control).
- **S0.11's chain test and pydantic.** Read as `str()`, the chain test would catch pydantic echoing a refused data key, because `input_value` is in the error text (measured). R7B1-11 covers the case the test misses.
- **The data client's error path.** Every HTTP call goes through `_request` (`client.py` L283–351), so every refusal by requests becomes `JuniperDataClientError("Request failed: …")`. The plan's single point for the source fix is right.
- **CI's rescan logs.** gitleaks-action passes `--redact` on every scan (saved copy L93–97), so a rescan's public log shows a hit's location, not its value.
- **Ignore files and allow markers.** No `.gitleaksignore` exists at the root of the ml, data, canopy, deploy, recurrence or cascor checkouts, and the directories checked hold no inline allow marker.
