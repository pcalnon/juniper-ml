F1  MAJOR  docs/REFERENCE.md:702
    What is wrong: the line reads "A failed `Verify PyPI serves exactly these files` is past the ladder: the step runs after
    the upload, so the files are already on PyPI, and only a new patch version ships tested files under a clean version."
    That is true of only one of the step's two failures:
    - a MISMATCH (PyPI lists a file this run did not build, or with another sha256) does need a new patch version;
    - a TIMEOUT (the step gave up because PyPI's JSON had not listed the files yet) does not. PyPI already holds this run's
      tested bytes, and the template's recovery is "Re-run failed jobs".
    juniper-cascor's docs/ci_cd/MANUAL.md keeps the two apart:
    - :819 gives "only a new patch version ships tested files under a clean version" for the mismatch row alone;
    - :821 "A JSON check gives up after 20 attempts" says "Re-run failed jobs: the index accepts a re-upload of identical
      files, and the check runs again. Re-running the PyPI job needs a fresh approval".
    cascor's docs/ci_cd/REFERENCE.md has no blanket patch-version advice; "past the ladder" is the port's own text. So an
    operator whose PyPI check timed out would cut a patch version they do not need, and might think the published version
    is not clean. No wrong bytes are published, but that is the wrong recovery.
    How shown: I read cascor MANUAL_main.md:819 and :821 (copied from clones/juniper-cascor HEAD) against the head's
    REFERENCE.md:702. The same line's second sentence ("Each rung acts on the workflow file as of the tag…") is correct.
    Proposed fix: split the first sentence. For example: "A `Verify PyPI serves exactly these files` that fails because
    PyPI lists a file this run did not build, or with another sha256, is past the ladder: this run's files are already on
    PyPI beside another upload's, and only a new patch version ships tested files under a clean version. One that gave up
    waiting (PyPI's JSON did not list the files in time) is index lag: the files are already on PyPI, and Re-run failed
    jobs uploads the same bytes again, which the index accepts, and repeats the check (a fresh `pypi` approval)." Keep
    the bound's number out, since test_publish_docs_bounds.py pins only the install check's numbers.
