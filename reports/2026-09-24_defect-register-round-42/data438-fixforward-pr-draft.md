# fix(http): #438's round-1 follow-ups -- creates take the conditional PATCH's locks, sixteen fixed lock stripes, no read waits on the event loop, a stored file that leads out of the root is a 500

## Summary

**juniper-data#438 merged at 2026-09-24T18:52:00Z, as squash `0f0f7e0e`, WITHOUT the fixes its own round-1 validation asked for.** This PR is that fix-forward, based on `main` at `0f0f7e0e226e6046fc49541a4baa6dd1bd8b67ce`. It has two commits.

- **Round 1, `d1c66a11`.** Its specification is #438's round-1 validation: `data438-round1-laneA-reprobe.md`, which reproduced all eight of #438's items and found the headline guarantee still false for `POST /v1/datasets`, and `data438-round1-laneB-refute.md`, which returned REFUTED.
- **Round 2, `94ce8b1f` (`94ce8b1fa8e229c92e8674a1074d518e59142488`).** Its specification is the round-1 validation of THIS branch at `d1c66a11`: `data438-fixforward-round1-laneA-reprobe.md`, a re-derivation, and `data438-fixforward-round1-laneB-refute.md`, which returned REFUTED on one MEDIUM. Round 1 had moved a whole-service stall onto every create.

All four reports are archived in juniper-ml under `reports/2026-09-24_defect-register-round-42/`.

What changes, as of the second commit:

- **A create takes the conditional PATCH's two locks, and holds them only to commit.** `save_versioned` (`juniper_data/storage/base.py:589`) stages first, with no lock held. On LocalFS that means compressing and writing the artifact to a temporary file (`stage_save`, `juniper_data/storage/local_fs.py:426`). It then checks existence again and commits under `_version_lock` plus the cross-process lock, for named and unnamed datasets alike. The commit is the version, the metadata write and the renames. A create that finds the dataset there writes nothing and answers with the stored one, as a cache hit does. `POST /v1/datasets` and `/batch-create` both go through it.
- **No read waits on the event loop.** Every `GET /{id}` and artifact download hands its access to the access recorder, a single-thread executor of its own (`juniper_data/api/routes/datasets.py:85-134`), and answers without waiting. The lifespan shuts the recorder down after it records what is queued (`juniper_data/api/app.py:84`). A recording that fails is logged by type only. `GET /{id}/access` drains the recorder first (`juniper_data/api/routes/datasets.py:1100`).
- **LocalFS's lock files are sixteen fixed stripes, `locks/{0..f}.lock`,** stripe `sha256(id) mod 16` (`juniper_data/storage/constants.py:39-52`).
  - The store opens the storage root and `locks/` once and keeps both descriptors. It opens the root again, by path, only if that directory is removed and made again. It opens `locks/` with `O_DIRECTORY|O_NOFOLLOW`, and each stripe through that descriptor, with `O_NOFOLLOW`, `O_CLOEXEC` and no `O_CREAT` (`local_fs.py:147-382`).
  - So an absent id leaves no file behind, a symlink planted at a stripe is refused, and a `locks` swapped for a symlink after startup is never followed.
  - Anything at `locks` that is not a real directory stops the store from opening.
  - When a stripe is missing and cannot be made (a volume out of inodes, say), the lock is the storage root itself, taken `LOCK_EX`, which needs no inode. Every stripe lock holds the root `LOCK_SH`.
  - The per-id lock files an earlier version left are removed when the store opens.
- **A stored file that leads out of the storage root is a generic `500`.** The app's `ValueError` handler answers `StorageContainmentError` that way, logged by type only (`juniper_data/api/app.py:242`). `/filter` decodes its cursor before it calls the store (`juniper_data/api/routes/datasets.py:608`), so no store error's text reaches a 400 detail. This covers such files only. A metadata document that does not parse is still the caller's `400`, a known issue.
- **No access is recorded for a download whose metadata the store refused** as leading out of the root (`datasets.py:1154-1232`), so asyncio no longer logs a traceback carrying the id. Any other metadata failure still records the access.
- **The lock order is pinned by a test,** plus harness arms M51 and M65-M67.
- **Docs and CHANGELOG corrected** as each finding below says. The "*Moved here from `[0.16.0]`…*" note is removed from `[Unreleased]`. `[0.16.0]` is byte-identical to the `v0.16.0` tag's section: 261 lines.
