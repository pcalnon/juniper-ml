## Why this file exists

A subagent's report lives only in its transcript (`~/.claude/projects/<slug>/<session>/subagents/agent-<id>.jsonl`), which is local, unversioned and swept after `cleanupPeriodDays`. The standing rule is to archive validator reports verbatim into `notes/` as soon as they land. The sections headed `## Report …` below were copied from the transcripts by `util/ad-hoc/2026-09-23_archive_subagent_reports.py`, not retyped, so they are the agents' words and any error in them is the agent's; the reconciliation section is the orchestrator's and says which findings were re-derived, accepted, or recorded as dissent.

- The API-signed commit path as the only signing route for an unattended executor (§6.5) — with #12's remote-base check.

## 3. The alternative steelmanned, and the break-even

**Alternative**: a systemd timer (the SOAK unit shape already in the repo) runs `plan_cycle.py` and launches one `claude -p <validated prompt> --output-format stream-json --session-id <uuid> --permission-prompts none` child per selected task (plus the existing `--allowedTools` set), each in an ecosystem worktree the launcher creates for the task's *actual* repo; a child that dies on `error: rate_limit` is re-launched after `resetsAt` with `--resume <session id>` ("Claude Code finds the session by its ID in any project on this machine"; "When you resume the session, Claude Code continues the turn that SIGTERM left unfinished") — the same resume-in-place R1 observed, without the workflow's replay of every later agent. The odometer keeps its status-line writer, hosted by one minimal interactive session in an empty directory (`/loop 10m` no-op; ~15–20 K context) rather than by a 40 K+ dispatcher.

What it gives up: the workflow pause — which §8.4 forbids relying on ("Never rely on the pause"), which is bounded to two waits per run and none for the weekly wall, and which *restarts* waiting agents rather than resuming them. What it gains, each documented: a timer that fires regardless of idleness (no "fires only while idle", no missed-fire loss, no `/loop` re-arm, no seven-day expiry); no per-tick full-context turn (#9); no handoff-at-40-ticks machinery (each child is a fresh context; the controller is a script); deterministic permissions (`--permission-prompts none`, #16); a worktree per task in the right repo (#11); no replay of non-idempotent stages (#17); no `Date.now()`/no-filesystem constraints on the controller.

**Break-even**: the interactive/Workflow surface is worth its costs only where the pause is load-bearing, i.e. where cycles are frequently interrupted mid-flight by a 5-h reset they can wait out. The design's own duration guard (`Σ D ≤ r − margin`) and slack are built to make that rare, and the weekly wall — the binding one at any plausible `k` (§8.3) — cannot be waited out on either surface. At the illustrative `k = 100K` the loop's idle overhead (#9, ≥ 1 M input tokens/day) already matches its projected output (≈ 1 M task-tokens/day); for the pause to pay, `k` must be large enough that throughput dwarfs 24 × context per day (≳ 5–10× the illustration) — and that is precisely the regime in which walls, and therefore pauses, are rarest. I could not construct a measured `k` at which the chosen primitive beats the timer on the design's own criteria. The one property the alternative cannot supply on its own is an odometer refreshed while every human session sleeps; that needs one live interactive session, not a dispatcher.

- Whether the WIP-commit tree is treated as "changed" by the runtime's auto-removal for every shape of WIP (the docs say changed trees stay).
- Lane A's measurements (granted per brief) and V3's correctness beyond the two gates I ran; my B1/B3 probe used six branches, all consistent, none contradicting.
