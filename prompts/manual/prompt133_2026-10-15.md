# Environment configuration

Juniper Project development environment and computational resource configuration.

## Background

Bring online a new Juniper project host, named turing, currently in a partially configured and unverified state.

### Role

You are a senior architect and experienced software engineer working on the small Juniper project team.

### Environment

The current dev environment is a macbook pro, 15 inch named turing.
The macbook is running a 2.6 GHz 6-Core Intel Core i7 cpu with 16 GB 2400 MHz DDR4 and a Radeon Pro 560X 4 GB Intel UHD Graphics 630 1536 MB card.
Turing is running MacOS Sequoia 15.7.1 (24G231).
Turing is one of the machines documented in the k8s primer and architecture documentation, and we are now in the process of updating its configuration and bringing it into line with its role in Juniper project documentation.
In addition to being used to run ubuntu VMs for k8s operation and computation, turing will also being used as a secondary development environment (in addition to the primary, yamaguchi workstation.)

## Deliverables

Create a detailed and comprehensive development plan to bring the turing host into line with its expected and documented configuration.

### Requirements

This development plan should address turing's current state and its documented configuration, determined by a review of existing notes documentation, complete with any necessary updates or modifications.
The plan should include detailed prioritization, a breakdown of task dependenciess and orthagonal work arcs.

The plan should include implementation of any local scripts and github actions needed to normalize pre-commit checks, local envioronment and remote github platform testing, as well as any appropriate checks, gates, and metrics.
The plan should include unit, regressions, and integration tests as appropriate for any code or script changes made.
Comprehensive requirements to create apropriate tests, checks, gates, and metrics for all code changes and new development carried out in this work arc should also be included in this development plan.
All actions taken and choices made during the creation of this development plan, including any investigation, analysis, and validation work, should also be rigorously documented and included in (or directly referenced and linked to) in this plan.

## Known Issues

Code signing and github authentication are failing for several of the newer repos (including juniper-k8s, juniper-recurrence, etc) while working correctly for others.
The environment is intended to function using either of 2 yubikeys, yubikey 3c and yubikey 3a, that contain gpg keys including subkeys that can be used for ssh auth.
Additionally, turing has a repo specific ed25519 ssh key for each active repo that should allow passwordless and automated git commands.
The repo-specific keys are located in the "${HOME}/.ssh" directory and are named as follows: id_ed25519_github_juniper-<REPO> (e.g., id_ed25519_github_juniper-canopy).
Some work has been done to move the turing laptop's keys into the juniper project's github enviornment, but this work is incomplete.
